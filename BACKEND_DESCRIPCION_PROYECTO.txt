• ¿Qué BD se usa?
- Laravel usa la conexión definida por la variable de entorno DB_CONNECTION (archivo config/database.php).
- En este proyecto la configuración por defecto en config/database.php toma env('DB_CONNECTION', 'sqlite'), por lo que si no hay una variable de entorno definida el proyecto cae en SQLite (archivo local).
- En entornos de desarrollo/producción habituales se suele usar MySQL o PostgreSQL; la app ya tiene conexiones configuradas para mysql, pgsql, sqlite, sqlsrv.
- Para saber cuál se está usando en una instalación concreta, revisar el .env (clave DB_CONNECTION) o el archivo config/database.php.

• ¿Qué es un ORM?
- ORM = Object-Relational Mapping. Es una capa que permite trabajar con la base de datos mediante objetos del lenguaje en lugar de consultas SQL crudas.
- Ventajas: modelos como objetos, relaciones definidas en código, consultas legibles, protección frente a inyección SQL cuando se usan correctamente.

o Eloquent (Laravel)
- Eloquent es el ORM nativo de Laravel. Cada tabla suele corresponder a un "Model" (por ejemplo App\Models\Testimonio).
- Los modelos en este proyecto se encuentran en app/Models/ y representan las tablas del proyecto.
- Eloquent permite operaciones CRUD sencillas: Model::create([...]), Model::find($id), relaciones (hasMany, belongsTo, etc.), scopes, mutators/accessors y casting.

• Validaciones del lado del servidor:
- Regla general: validar siempre en el servidor (no confiar únicamente en validación frontend).
- En este proyecto las validaciones server-side están implementadas principalmente en formularios Livewire (clases en app/Livewire/Forms/):
  - app/Livewire/Forms/ContacForm.php  (formulario de contacto)
  - app/Livewire/Forms/TestimonioForm.php (formulario de testimonios)

- Reglas en los controladores / formularios (ejemplos resumidos):
  - Contacto (ContacForm):
    - name: required, string, min:3, max:50, regex para caracteres permitidos
    - email: required, email, max:50
    - subject: required, string, min:5, max:20
    - message: required, string, min:10, max:90
  - Testimonios (TestimonioForm):
    - name: required, string, min:3, max:20
    - role: required, string, min:3, max:20
    - text: required, string, min:10, max:50
    - rating: required, integer, min:1, max:5

- Mensajes y manejo de errores enviados al usuario:
  - En las clases Livewire se define un array messages() con mensajes personalizados en español. Ejemplos:
    - 'name.required' => 'El nombre es obligatorio.'
    - 'text.max' => 'El comentario no puede exceder 50 caracteres.'
  - Flujo de validación:
    1. En el método del formulario se llama a $this->validate() (Livewire/Laravel). Si falla, Laravel lanza una ValidationException.
    2. Livewire captura el error y lo expone al frontend; en las vistas Blade se usan directivas @error('form.field') para mostrar el mensaje al usuario (se muestran los mensajes definidos en messages()).
    3. Si la validación pasa, el controlador/form guarda el registro con Model::create([...]) y normalmente hace session()->flash('success', '...') para confirmar al usuario.

- Ejemplo compacto de validación (presentación):
  - Regla (en código):
     'text' => 'required|string|min:10|max:50|not_regex:/^\s+$/' 
  - Mensaje personalizado (en messages()):
     'text.max' => 'El comentario no puede exceder 50 caracteres.' 
  - Resultado para el usuario: Blade/Livewire mostrará el mensaje en la vista justo debajo del campo (p. ej. @error('form.text') <div class="text-danger">{{ $message }}</div> @enderror).
